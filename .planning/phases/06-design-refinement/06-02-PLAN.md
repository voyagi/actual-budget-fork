**1. Add and export the RetryPolicy type and applyJitter function** (after the existing `sleep` function, around line 63):

```typescript
export type RetryPolicy = {
  maxRetries: number;
  initialDelay: number;
  multiplier: number;
  maxDelay: number;
  jitterFraction: number;
};

export function applyJitter(delay: number, jitterFraction: number): number {
  const jitter = (Math.random() * 2 - 1) * jitterFraction; // range: [-fraction, +fraction]
  return Math.round(delay * (1 + jitter));
}
```

**2. Add and export the syncAccountWithRetry function** (after applyJitter):

```typescript
export async function syncAccountWithRetry(
  syncFn: () => Promise<void>,
  sleepFn: (ms: number) => Promise<void>,
  policy: RetryPolicy,
  accountLabel: string,
): Promise<void> {
  let delay = policy.initialDelay;

  for (let attempt = 0; attempt <= policy.maxRetries; attempt++) {
    try {
      await syncFn();
      return; // success
    } catch (err) {
      // RateLimitError and SessionExpiredError bypass retry - propagate immediately
      if (err instanceof RateLimitError || err instanceof SessionExpiredError) {
        throw err;
      }
      if (attempt === policy.maxRetries) {
        throw err; // final attempt exhausted - propagate to caller for eb_sync_log write
      }
      const jitteredDelay = Math.min(
        applyJitter(delay, policy.jitterFraction),
        // Apply jitter first, then cap. Jitter on a capped value could still exceed max,
        // so we cap the final result.
        policy.maxDelay + Math.round(policy.maxDelay * policy.jitterFraction),
      );
      console.log(
        `[scheduler] Retry ${attempt + 1}/${policy.maxRetries} for ${accountLabel} in ${jitteredDelay}ms`,
      );
      await sleepFn(jitteredDelay);
      delay = Math.min(delay * policy.multiplier, policy.maxDelay);
    }
  }
}
```

Wait -- the cap logic above is wrong per the CONTEXT.md spec. The max delay cap of 60s means the BASE delay is capped, and jitter applies on top. Let me correct: the jitteredDelay should be `applyJitter(Math.min(delay, policy.maxDelay), policy.jitterFraction)`. This means:
- delay starts at 5000, jitter applied -> ~4000-6000
- delay becomes 10000, jitter applied -> ~8000-12000
- delay becomes 20000, jitter applied -> ~16000-24000
- If delay somehow exceeds maxDelay (60000), it's capped to 60000 before jitter -> ~48000-72000

The correct implementation:

```typescript
const cappedDelay = Math.min(delay, policy.maxDelay);
const jitteredDelay = applyJitter(cappedDelay, policy.jitterFraction);
```

This allows jitter to slightly exceed maxDelay (by up to jitterFraction), which is the standard pattern.
