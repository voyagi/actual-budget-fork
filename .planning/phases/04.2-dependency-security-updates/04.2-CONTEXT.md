<decisions>
## Implementation Decisions

### Update Strategy
- Lockfile refresh first (`yarn install --refresh-lockfile`) to pick up already-updated ranges in package.json (axios ^1.13.5, lodash ^4.17.23, jws ^4.0.1)
- After refresh, surgical fixes for remaining CVEs grouped into two commits: HIGH severity first, MEDIUM severity second
- If lockfile refresh resolves a CVE, skip it in the surgical pass. No unnecessary pins or resolution overrides
- On breakage: case by case. Fix forward for small breaks, defer complex ones with a pinned safe version + TODO

### Storybook Handling
- Keep Storybook for upstream merge compatibility (not contributing upstream, but monthly merges are easier without deleted packages)
- Update to 10.2.10 (patch bump within ^10.2.0 range)
- Researcher should determine how many transitive CVEs Storybook pulls in
- If the Storybook update breaks, defer it under the case-by-case breakage rule

### Verification Depth
- Full CI suite after each step: `yarn build` + `yarn test` + `yarn typecheck` + oxfmt check
- Run `trivy fs .` as final gate to confirm CVE remediation
- Best effort tolerance: resolve all actionable CVEs, document any remaining (deep transitive with no available fix)

### Rollup Pin Investigation
- Root package.json has `"rollup": "4.40.1"` in resolutions (the vulnerable version, sec-9 RCE)
- Investigate why it was pinned (git blame) before bumping, regardless of whether pin is upstream or fork-added
- Same caution applies: pin exists for a reason, understand it first

### Claude's Discretion
- Exact yarn commands for lockfile refresh vs targeted upgrades
- Which resolution overrides to add for transitive deps (minimatch, etc.)
- Whether to use `yarn up` vs manual package.json edits
- Commit message wording and grouping within HIGH/MEDIUM batches
- How to handle glob 10.5.0 and ajv 8.18.0 (not in sec-8 to sec-14 but listed in phase goal)

</decisions>
