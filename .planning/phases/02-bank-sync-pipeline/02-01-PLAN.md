    **enablebanking-service.js** - Add 6 new exported functions to the existing file (keep `loadPrivateKey`, `generateJWT`, `ebRequest`, `testAuth` unchanged):

    1. `getAspsps(country)` - calls `ebRequest('GET', '/aspsps?country=' + country)`, returns `response.data`
    2. `createAuth({ aspspName, aspspCountry, redirectUrl, state })` - calls `ebRequest('POST', '/auth', { aspsp: { name: aspspName, country: aspspCountry }, redirect_url: redirectUrl, state, access: { valid_until: new Date(Date.now() + 90 * 24 * 60 * 60 * 1000).toISOString().split('T')[0] } })`, returns `response.data` (contains `{ url, state }`)
    3. `exchangeCode(code)` - calls `ebRequest('POST', '/sessions', { code })`, returns `response.data` (contains `{ session_id, accounts, valid_until }`)
    4. `getSessionAccounts(sessionId)` - calls `ebRequest('GET', '/sessions/' + sessionId)`, returns `response.data`
    5. `getTransactions(accountUid, startDate, continuationKey)` - calls `ebRequest('GET', '/accounts/' + accountUid + '/transactions?date_from=' + startDate + (continuationKey ? '&continuation_key=' + continuationKey : ''))`. Implements pagination loop: if response contains `continuation_key`, fetch next page and concat. **SAFEGUARD:** Add `maxPages = 100` limit to the pagination loop. If the limit is hit, log a warning (`logger.warn('getTransactions: hit maxPages limit (100) for account ' + accountUid)`) and return the results collected so far rather than looping indefinitely. Returns `{ booked: [...], pending: [...] }` arrays.
    6. `getBalances(accountUid)` - calls `ebRequest('GET', '/accounts/' + accountUid + '/balances')`, returns `response.data`

    **utils.js** - Create new file with 3 exported functions:

    1. `normalizeTransaction(ebTransaction, isBooked)` - Maps Enable Banking snake_case to camelCase GoCardless-compatible format. CRITICAL sign convention: `credit_debit_indicator === 'CRDT' ? 1 : -1` multiplied by `parseFloat(transaction_amount.amount)`. Payee: `credit_debit_indicator === 'DBIT' ? creditor?.name : debtor?.name`, with fallbacks to `remittance_information?.[0]` then `'Unknown'`. Sets `booked: isBooked`. Returns: `{ transactionId, internalTransactionId, transactionAmount: { amount: String(signedAmount) }, booked, bookingDate, valueDate, date: booking_date || value_date (formatted yyyy-MM-dd), payeeName, notes: remittance_information?.[0] || null, remittanceInformationUnstructured }`.

       **CRITICAL**: The `date` and `notes` top-level fields are REQUIRED. loot-core's `normalizeBankSyncTransactions` in sync.ts uses `defaultMappings` which reads `trans['date']` and `trans['notes']` (not `bookingDate` or `remittanceInformationUnstructured`). Without `date`, every transaction throws "`date` is required". Without `notes`, all transactions get null notes. The `date` value must be the booking_date (preferred) or value_date, formatted as `yyyy-MM-dd` string.

    2. `normalizeAccount(ebAccount, sessionId)` - Maps Enable Banking account to `SyncServerEnableBankingAccount` shape: `{ account_id: ebAccount.account_id || ebAccount.uid, name: ebAccount.account_name || ebAccount.iban, institution: ebAccount.aspsp_name || '', mask: (ebAccount.iban || '').slice(-4), official_name: ebAccount.product || null, balance: null, iban: ebAccount.iban || null, session_id: sessionId }`.

       **IMPORTANT:** The `account_id` derivation uses `ebAccount.account_id || ebAccount.uid` - this same derivation MUST be used in the `/callback` route when inserting into `eb_account_map.eb_account_uid` to ensure consistency.

    3. `extractBalance(balances)` - Picks best balance type by priority: CLAV > ITAV > ITBD > CLBD. Returns `Math.round(parseFloat(bal.balance_amount.amount) * 100)` (integer minor units) or `null` if no balance found. The sign for balance follows the same CRDT/DBIT convention if `credit_debit_indicator` is present on the balance object, otherwise assume positive.
