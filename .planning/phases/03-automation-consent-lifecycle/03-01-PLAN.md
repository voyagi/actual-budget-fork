**Create `packages/sync-server/src/scheduler.ts`:**

1. Import `cron` from `node-cron`, `getAccountDb` from `./account-db.js`, `getTransactions`, `getBalances` from `./app-enablebanking/enablebanking-service.js`, and `normalizeTransaction` from `./app-enablebanking/utils.js`. Do NOT import `axios` - the scheduler calls EB API functions directly, not via internal HTTP.

2. Export `startScheduler()` function:
   - Check `process.env.ENABLE_AUTO_SYNC !== 'true'` - if not set, log `[scheduler] Auto-sync disabled (ENABLE_AUTO_SYNC not set to true)` and return early.
   - Call `cron.schedule('0 0,6,12,18 * * *', handler)` (standard 5-field cron: at minute 0, hours 0/6/12/18). Using the explicit 5-field form instead of 6-field `0 0 */6 * * *` because node-cron v4's 6-field second-precision format is version-sensitive and harder to verify.
   - Log `[scheduler] Auto-sync scheduled (every 6 hours)` on successful registration.

3. The cron handler (multi-user aware per CONTEXT.md locked decision):
   - Log `[scheduler] Starting scheduled sync run`.
   - **Group accounts by session (each session = one user's bank connection):**
     Query all linked EB accounts joined with their session data:
     ```sql
     SELECT m.actual_account_id, m.eb_account_uid, m.session_id,
            s.valid_until, s.aspsp_name
     FROM eb_account_map m
     JOIN eb_sessions s ON s.id = m.session_id
     WHERE m.actual_account_id IS NOT NULL
     ORDER BY m.session_id
     ```
   - Group the result rows by `session_id` into a `Map<string, AccountRow[]>`. Each group represents one user's bank connection (one OAuth session with one bank).
   - **Process each session group independently:**
     For each `[sessionId, accounts]` entry in the grouped map:
     a. Check consent expiry once per session (not per account): if `valid_until` exists and `new Date(valid_until) < new Date()`, log `[scheduler] Skipping session ${sessionId} (${aspsp_name}): consent expired (${accounts.length} accounts)` and `continue` to the next session group.
     b. For each account in the group, call `syncOneAccount(account)` (see below).
     c. **Error handling (differentiate by error type):**
        - On `RateLimitError` (HTTP 429): log `[scheduler] Rate limited on session ${sessionId} (${aspsp_name}), skipping remaining accounts in session`, `break` out of the account loop, and `continue` to the next session group. Do NOT sleep or retry - a 429 applies to the entire API connection. Sleeping 30s per account compounds to N x 30s across the session (e.g. 50 accounts = 25 minutes of sleeping).
        - On `SessionExpiredError`: log `[scheduler] Session ${sessionId} expired mid-sync, skipping remaining accounts`, `break` out of the account loop.
        - On all other errors (network timeouts, 5xx): wait 30 seconds (`setTimeout` wrapped in Promise), retry once. On retry failure: log error and insert into `eb_sync_log` with status='error', then continue to next account.
     d. Log `[scheduler] Session ${sessionId} (${aspsp_name}): synced ${successCount}/${accounts.length} accounts`.
   - Log `[scheduler] Sync run complete. ${totalSessions} sessions, ${totalSynced} accounts synced, ${totalErrors} errors.`
   - **Why group by session:** Each session belongs to one user's bank authorization. Grouping ensures (a) consent expiry is checked once per bank connection, not per account, (b) errors in one user's bank connection don't affect another user's sync, and (c) logging is meaningful ("ING Bank session: 3/3 accounts synced" vs flat account list).

4. `syncOneAccount(account)` helper:
   - **CRITICAL: The scheduler runs on the sync-server, not in loot-core.** Do NOT import loot-core modules. Call the EB API functions directly (`getTransactions`, `getBalances` from `enablebanking-service.ts`) and write results to `eb_sync_log`. This avoids needing auth headers for internal HTTP calls (per RESEARCH.md Pitfall 2).
   - The direct approach: call `getTransactions(account.eb_account_uid, sinceDate)` and `getBalances(account.eb_account_uid)` (neither function takes a sessionId parameter), then `normalizeTransaction()` each transaction, and insert a success entry into `eb_sync_log`:
     ```sql
     INSERT INTO eb_sync_log (actual_account_id, eb_account_uid, status, transactions_added)
     VALUES (?, ?, 'ok', ?)
     ```
     This matches the existing error-path INSERT pattern in `app-enablebanking.ts` lines 283-292 and satisfies the NOT NULL constraints on `actual_account_id`, `eb_account_uid`, and `status`.
   - **sinceDate derivation (epoch-to-date conversion):** `eb_sync_log.synced_at` is a Unix epoch INTEGER (not a text timestamp). Query the most recent `synced_at`, then convert:
     ```typescript
     const row = db.first(
       'SELECT synced_at FROM eb_sync_log WHERE actual_account_id = ? ORDER BY id DESC LIMIT 1',
       [account.actual_account_id],
     );
     const sinceDate = row?.synced_at
       ? new Date(Number(row.synced_at) * 1000).toISOString().split('T')[0]
       : new Date(Date.now() - 90 * 24 * 3600 * 1000).toISOString().split('T')[0];
     ```
     The EB API expects YYYY-MM-DD for `date_from`. The conversion multiplies the epoch seconds by 1000 (to milliseconds), creates a Date, and extracts the date portion.
   - Log each account sync: `[scheduler] Synced ${account.actual_account_id}: ${transactions.length} transactions`.

**Extend /sync-status in `app-enablebanking.ts`:**

Modify the existing `/sync-status` route handler (lines 330-347). For each accountId in the loop, after fetching the `lastEntry` from `eb_sync_log`, also look up the consent expiry:

```typescript
const mapRow = db.first(
  'SELECT session_id FROM eb_account_map WHERE actual_account_id = ?',
  [accountId],
);
const session = mapRow
  ? db.first('SELECT valid_until, aspsp_name FROM eb_sessions WHERE id = ?', [mapRow.session_id])
  : null;

// Null-guard: when lastEntry is null (account linked but never synced),
// ...null produces {} which drops status, synced_at, error_message etc.
// Provide explicit defaults so the client always sees all expected fields.
const defaultEntry = {
  synced_at: null,
  status: null,
  error_message: null,
  transactions_added: 0,
  transactions_updated: 0,
  error_code: null,
};

statuses[accountId] = {
  ...(lastEntry ?? defaultEntry),
  // Convert synced_at from Unix epoch integer to ISO string for the client
  synced_at: lastEntry?.synced_at
    ? new Date(Number(lastEntry.synced_at) * 1000).toISOString()
    : null,
  consent_valid_until: session?.valid_until ?? null,
  session_id: mapRow?.session_id ?? null,
  aspsp_name: session?.aspsp_name ?? null,
};
```

This extends the response shape to include `consent_valid_until` (ISO date string), `session_id` (for re-auth grouping), and `aspsp_name` (for banner display like "ING Bank connection expires March 15"). The `synced_at` field is serialized from its raw Unix epoch integer to an ISO string so the client receives a consistent string format. The other existing fields (`status`, `error_message`) remain unchanged.
