3. **Add bank sync check on visibility/focus** (CONTEXT.md: "also trigger sync on window/tab focus if the stale threshold has passed"). In FinancesApp (not App.tsx, because useLocalPref requires budget context), add a useEffect that listens to both `visibilitychange` and `focus` events:
   **IMPORTANT:** Use `useRef` for the `isSyncing` mutex instead of a closure-scoped `let`. The `useEffect` has `[staleThresholdHours]` in its deps - when the pref changes, React creates a new closure with `isSyncing = false`, which would allow concurrent syncs. A `useRef` persists across re-renders and effect re-creations.

   ```
   // Declare useRef OUTSIDE the useEffect, at component level:
   const isSyncingRef = useRef(false);

   useEffect(() => {
     async function onVisibilityOrFocus() {
       // NOTE: App.tsx fires dispatch(sync()) (CRDT sync) on the same
       // visibilitychange event. These run concurrently, there is no
       // ordering guarantee. This is acceptable because:
       // - Bank sync reads from the EB API, not from local DB, so
       //   CRDT state doesn't affect the fetch.
       // - The CRDT sync on focus is typically a lightweight no-op
       //   (checking for remote changes).
       // - EB API calls are idempotent.
       // The init() function serializes them (CRDT first, then bank sync)
       // because init runs once at load time and can afford the wait.
       if (document.hidden || isSyncingRef.current) return;
       isSyncingRef.current = true;
       try {
         const accounts = await send('accounts-get');
         const linkedAccounts = (accounts || []).filter(a => a.account_sync_source && a.account_id);
         const effectiveThreshold = (staleThresholdHours ?? 6) * 60 * 60 * 1000;
         const now = Date.now();

         const linkedIds = linkedAccounts.map(a => a.id);
         const syncStatuses = linkedIds.length > 0
           ? (await send('enablebanking-sync-status', { accountIds: linkedIds }))?.statuses ?? {}
           : {};
         const staleIds = linkedAccounts
           .filter(a => {
             const status = syncStatuses[a.id];
             if (status?.consent_valid_until && new Date(status.consent_valid_until) <= new Date()) return false;
             const lastSync = a.last_sync ? parseInt(a.last_sync, 10) : 0;
             return (now - lastSync) > effectiveThreshold;
           })
           .map(a => a.id);
         if (staleIds.length > 0) {
           send('accounts-bank-sync', { ids: staleIds }).catch(() => {});
         }
       } catch (e) {
         // Non-blocking: don't surface errors from background sync check
       } finally {
         isSyncingRef.current = false;
       }
     }

     window.addEventListener('visibilitychange', onVisibilityOrFocus);
     window.addEventListener('focus', onVisibilityOrFocus);
     return () => {
       window.removeEventListener('visibilitychange', onVisibilityOrFocus);
       window.removeEventListener('focus', onVisibilityOrFocus);
     };
   }, [staleThresholdHours]);
   ```
   **NOTE:** This uses a closure-scoped `isSyncing` mutex (matching the existing App.tsx pattern) to prevent overlapping syncs on rapid tab focus/unfocus. App.tsx's existing visibilitychange handler (CRDT sync only) is left untouched.

**Add re-auth server support in `app-enablebanking.ts`:**

Add a new POST `/reauth-complete` route. **CRITICAL: place this AFTER the `validateSessionMiddleware` (line 117)** to ensure authentication. Routes before line 117 are unauthenticated.

```typescript
app.post('/reauth-complete', handleError(async (req, res) => {
  const { newSessionId, oldSessionId } = req.body || {};
  if (!newSessionId || !oldSessionId) {
    return res.send({ status: 'ok', data: { error_code: 'INVALID_INPUT' } });
  }
  const db = getAccountDb();

  // Update all account map rows from old session to new session
  db.mutate(
    'UPDATE eb_account_map SET session_id = ? WHERE session_id = ?',
    [newSessionId, oldSessionId],
  );

  // Log the re-auth event
  console.log(`[eb] Re-auth complete: session ${oldSessionId} -> ${newSessionId}`);

  res.send({ status: 'ok', data: {} });
}));
```

This is the ONLY server-side re-auth mechanism. There is no `/callback` modification for re-auth. The flow is: modal re-auth -> new session via existing createAuth/exchangeCode/callback -> client calls `/reauth-complete` to swap session IDs in the map.
