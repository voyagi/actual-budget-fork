**Password 8-char minimum on bootstrap/change, OpenID redirect restricted to server_hostname scheme+host+port, regex helpers protected with escapeRegExp and nested-quantifier pre-check**

## Accomplishments
- Password strength validation rejects passwords under 8 characters on bootstrap and change, with existing short passwords still working for login
- OpenID redirect URL validation now matches scheme, hostname, and port against server_hostname, blocking open redirects in production while preserving localhost dev mode
- All three Handlebars regex helper non-regex branches now escape metacharacters before RegExp construction, preventing ReDoS from payee names with special characters
- Regex-literal branch protected by isRegexSafe pre-check that blocks nested quantifiers (the primary cause of catastrophic backtracking)
- All regex apply calls wrapped in try/catch with graceful fallback to original value

## Decisions Made
- **Synchronous regex protection instead of worker_threads timeout:** Handlebars templates are evaluated synchronously in action.ts (line 150: `object[this.field] = this.handlebarsTemplate({...})`). A Promise-returning helper would render as `[object Promise]`. Used isRegexSafe pre-check (rejects nested quantifiers like `(a+)+`) combined with try/catch as the synchronous alternative. This covers the most dangerous ReDoS patterns while maintaining Handlebars compatibility. The `regex-timeout.ts` file with worker_threads was not created since it cannot work with synchronous Handlebars.
- **escapeRegExp on replace/replaceAll non-regex branches:** Per locked CONTEXT.md decision for consistency, even though String.replace with a string argument does literal matching. Defense-in-depth.
