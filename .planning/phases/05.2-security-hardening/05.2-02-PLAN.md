    **openid.js changes (sec-5):**

    1. Replace the body of `isValidRedirectUrl` (lines 431-453) with scheme+hostname+port matching against server_hostname:

       ```javascript
       export function isValidRedirectUrl(url) {
         const serverHostname = getServerHostname();

         if (!serverHostname) {
           return false;
         }

         try {
           const redirectUrl = new URL(url);
           const serverUrl = new URL(serverHostname);

           const hostnamesMatch = redirectUrl.hostname === serverUrl.hostname;
           const portsMatch = redirectUrl.port === serverUrl.port;
           const schemesMatch = redirectUrl.protocol === serverUrl.protocol;

           if (hostnamesMatch && portsMatch && schemesMatch) {
             return true;
           }

           console.warn(
             `[openid] Blocked redirect URL: ${url} (server: ${serverHostname})`,
           );
           return false;
         } catch {
           return false;
         }
       }
       ```

       Key behaviors:
       - When server_hostname is `http://localhost:5006`, redirects to `http://localhost:5006/callback` are ALLOWED (dev mode)
       - When server_hostname is `https://budget.example.com`, redirects to `http://localhost:*` are BLOCKED (production)
       - Scheme mismatch (http vs https) is blocked to prevent HTTP downgrade attacks
       - Port mismatch is blocked
       - All three callers (app-account.ts:88, openid.js:157, app-openid.ts:106) use the boolean return and need no changes

    **handlebars-helpers.ts changes (sec-17):**

       ```typescript
       function escapeRegExp(str: string): string {
         return str.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
       }
       ```

    3. Change ONLY the `regex` helper's non-regex branch (line 53):
       - BEFORE: `value => new RegExp(value)`
       - AFTER: `value => new RegExp(escapeRegExp(value))`

    4. Do NOT change the `replace` or `replaceAll` helpers' non-regex branches (lines 58, 63) - they pass plain strings to `.replace()` / `.replaceAll()`, which is literal string matching (not regex). No vulnerability.

    5. Do NOT change the regex-literal branches (line 52, 57, 62) - these are user-authored `/regex/flags` patterns that should be interpreted as regex. Escaping would break them.

The regex-literal branch (`/pattern/flags`) is intentional user-authored regex. Worker thread complexity is disproportionate to the residual risk of intentional regex literals. Log a warning if regex execution throws an error (try/catch around the `apply` call).
