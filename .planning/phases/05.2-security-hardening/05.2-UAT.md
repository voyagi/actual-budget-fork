## Tests

### 1. Bootstrap rejects short password
expected: When setting up the server for the first time (bootstrap), entering a password shorter than 8 characters shows "Password must be at least 8 characters" error. A password of 8+ characters is accepted normally.
result: [pending]

### 2. Change password rejects short password
expected: When changing password in Settings, entering a new password shorter than 8 characters shows "Password must be at least 8 characters" error. A password of 8+ characters is accepted.
result: [pending]

### 3. Existing short passwords still work for login
expected: If you previously set a password shorter than 8 characters, you can still log in with it. The strength check only applies to new passwords and password changes, not existing logins.
result: [pending]

### 4. OpenID redirect restricted to server hostname
expected: OpenID authentication redirects only to URLs matching the server's own scheme, hostname, and port. In production (non-localhost server_hostname), redirects to localhost are blocked. In development (localhost server_hostname), localhost redirects work normally.
result: [pending]

### 5. Rules with special characters in payee names
expected: Creating a rule that uses the regex/replace/replaceAll helper with a payee name containing special regex characters (e.g., "McDonald's (Drive-Thru)", "AT&T", "$5 Store") works correctly without errors or hangs. The special characters are treated as literal text, not regex syntax.
result: [pending]

### 6. Dangerous regex patterns are blocked
expected: If a user enters a regex-literal pattern with nested quantifiers (e.g., /(a+)+$/) in a rule's regex helper, the pattern is rejected as unsafe rather than causing the app to hang from catastrophic backtracking. The original value is returned unchanged.
result: [pending]

### 7. Encrypted files still open after PBKDF2 upgrade
expected: Existing budget files that were encrypted before the PBKDF2 iteration upgrade (10K iterations) still decrypt and open correctly when you enter the password. The upgrade is transparent - no user action needed.
result: [pending]

### 8. New encryption uses stronger key derivation
expected: When setting up encryption on a new file or re-entering password on an existing file, the system uses 100,000 PBKDF2 iterations (up from 10,000). This is invisible to the user but can be verified by checking that encrypt metadata includes an iterations field.
result: [pending]
