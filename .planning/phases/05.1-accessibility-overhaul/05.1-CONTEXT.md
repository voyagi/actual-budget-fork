# Phase 05.1: Accessibility Overhaul - Context

**Gathered:** 2026-03-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Add semantic heading hierarchy to fork pages, form ARIA attributes (aria-required, aria-invalid, aria-describedby) to fork forms + fix FormError default, and extract consent urgency color/threshold/icon logic to a shared utility. Addresses audit findings a11y-3, a11y-6, dx-3.

</domain>

<decisions>
## Implementation Decisions

### Heading Hierarchy (a11y-3)
- Scope: Fork pages only (not upstream pages) to avoid merge conflicts on upstream sync
- Approach: Semantic HTML elements (`<h2>`, `<h3>`) replacing styled View/Text where section titles exist
- Fork pages in scope: ConsentExpiryBanner, BankSyncStatus, EnableBankingExternalMsgModal, SelectLinkedAccountsModal, EditSyncAccount, bank sync pages (banksync/ directory), MobileBankSyncPage, MobileBankSyncAccountEditPage
- `<h1>` remains in Page/PageHeader (upstream) - fork pages add `<h2>` for major sections, `<h3>` for subsections within

### Form ARIA Attributes (a11y-6)
- Fix FormError component in `@actual-app/components/form-error` to include `role="alert"` by default (currently inconsistent - some usages add it manually, some don't)
- Add `aria-required` to required form fields in fork components
- Add `aria-describedby` linking form fields to their FormError messages in fork components
- Add `aria-invalid` to form fields when validation errors are present in fork components
- Fork form files in scope: SelectLinkedAccountsModal (date inputs), any form fields in banksync/ components

### Urgency Utility Extraction (dx-3)
- Create new file: `packages/desktop-client/src/utils/consent-urgency.ts`
- Extract all three concerns into one module:
  - `urgencyColors`: theme token mapping per urgency level (currently duplicated in SessionBanner line 55 and MultiSessionBanner line 181)
  - `urgencyIcons`: SVG component mapping per urgency level (currently module-level const in ConsentExpiryBanner line 45)
  - `getUrgencyLevel(daysUntilExpiry: number)`: threshold function (currently inline in useEnableBankingStatus.ts line 166-174, thresholds: <=0 expired, <=7 urgent, <=14 soon)
- Update consumers: ConsentExpiryBanner.tsx (SessionBanner + MultiSessionBanner), useEnableBankingStatus.ts, AccountRow.tsx

### Claude's Discretion
- Which specific fork pages need `<h2>` vs `<h3>` (analyze each component's content structure)
- Exact aria-describedby id naming convention for form fields
- Whether to export urgency type as a union type or keep existing string type
- FormError component change approach (add role="alert" as default prop vs always render)

</decisions>
