<objective>
Add semantic heading hierarchy to fork pages and form ARIA attributes to fork form fields.

Purpose: Addresses a11y-3 (heading hierarchy) and a11y-6 (form ARIA) audit findings. Screen readers currently cannot navigate fork pages by heading because section titles use styled Text/View elements instead of semantic h2/h3 elements. FormError announces errors inconsistently because `role="alert"` must be passed explicitly per usage. Date and amount inputs in SelectLinkedAccountsModal lack accessible labels and required-field indicators.

Output: Semantic headings on all fork pages with section titles, FormError defaulting to role="alert", aria-label on unlabeled form inputs, and aria-required on required form fields.
</objective>

    **Step 2: Add `aria-label` and `aria-required` to SelectLinkedAccountsModal form fields**

    Edit `packages/desktop-client/src/components/modals/SelectLinkedAccountsModal.tsx`.

    In the `StartingOptionsFields` component there are TWO layout branches (inline and stacked). Both need aria-label and aria-required on their inputs.

    **Inline layout (around line 789-814):**

    Add `aria-label` and `aria-required` to the date Input:
    ```tsx
    <Input
      type="date"

        })
      }

    />
    ```

    Add `aria-label` and `aria-required` to the AmountInput:
    ```tsx
    <AmountInput
      value={customStartingDate.amount}
      aria-label="Starting balance"
      aria-required
      zeroSign={zeroSign}
      onUpdate={amount =>
        onSetCustomStartingDate(accountId, {
          ...customStartingDate,
          amount,
        })
      }
      style={{ width: '100%' }}
    />
    ```

    **Stacked layout (around line 839-868):**

    The stacked layout has visible `<Text>` labels ("Starting date:" and "Balance on that date:") but they are NOT `<label htmlFor>` elements, so the inputs still need explicit `aria-label`. Add `aria-label` and `aria-required` to BOTH inputs in the stacked layout:

    Date Input in stacked layout (around line 839):
    ```tsx
    <Input
      type="date"
      aria-label="Starting date"
      aria-required
      value={customStartingDate.date}
      onChange={...}
      style={{ width: '100%' }}
    />
    ```

    AmountInput in stacked layout (around line 861):
    ```tsx
    <AmountInput
      value={customStartingDate.amount}
      aria-label="Starting balance"
      aria-required
      zeroSign={zeroSign}
      onUpdate={...}
    />
    ```

    **Why `aria-required` is appropriate:** The StartingOptionsFields component is only rendered when the user is creating a new account (controlled by `shouldShowStartingOptions`). When visible, both date and amount are required to configure the starting balance. The date defaults to 90 days ago and amount defaults to the external balance, but once the user customizes them the fields are mandatory for the link operation to proceed correctly.

    **Why `aria-describedby` and `aria-invalid` are NOT added here:** Codebase audit confirms SelectLinkedAccountsModal has zero FormError instances, zero validation error messages, and zero error state variables. There are no error messages to link via aria-describedby, and no invalid state to signal via aria-invalid. The same applies to banksync/ form fields: BankSyncCheckboxOptions uses LabeledCheckbox (already accessible, no validation), and EditSyncAccount has no form inputs with validation error messages. If validation is added to these components in a future phase, aria-describedby and aria-invalid should be added at that time following the SingleInputModal pattern shown in the interfaces section above.
