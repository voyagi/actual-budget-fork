## Decisions Made

- Inline styles on heading elements reset browser defaults (`margin: 0`, `fontWeight: 'inherit'`) to preserve the exact visual appearance of the replaced Text components. This avoids any visual regression from the h2/h3 default browser margin/bold weight.
- AmountInput forwards aria-label and aria-required to the inner Input element only, not the sign toggle Button. The sign button has its own aria-label ("Make positive"/"Make negative"). The Input is the actual data input field that assistive technology needs to identify.
- The aria-required attribute is appropriate for both date and amount inputs in StartingOptionsFields because these fields are required whenever the component is visible (only shown during new account creation with custom starting options).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Import ConsentUrgency type for use within useEnableBankingStatus.ts**
- **Found during:** Task 1 push (pre-push hook triggered typecheck)
- **Issue:** `useEnableBankingStatus.ts` used `ConsentUrgency` as a type annotation at 5 locations but only re-exported it (`export type { ConsentUrgency } from ...`). A re-export statement does not bring the type into scope in the current module. TypeScript reported TS2304 "Cannot find name 'ConsentUrgency'" for all 5 usages, blocking the pre-push typecheck hook.
- **Fix:** Added `import { getUrgencyLevel, type ConsentUrgency } from '@desktop-client/utils/consent-urgency'` alongside the existing re-export statement.
- **Files modified:** `packages/desktop-client/src/hooks/useEnableBankingStatus.ts`
- **Verification:** `npx tsc --noEmit` produces no errors
- **Committed in:** `64eb9028d` (separate fix commit between Task 1 and Task 2)

**2. [Rule 2 - Missing Critical] Add aria-label/aria-required props to AmountInput**
- **Found during:** Task 2 (adding ARIA attributes to SelectLinkedAccountsModal)
- **Issue:** `AmountInput`'s `AmountInputProps` type did not include `aria-label` or `aria-required`. Adding these attributes directly to `<AmountInput>` in SelectLinkedAccountsModal would cause a TypeScript error since they were not in the props type.
- **Fix:** Added `'aria-label'?: string` and `'aria-required'?: boolean | 'true' | 'false'` to `AmountInputProps`, destructured them with alias syntax in the function signature, and forwarded them to the inner `Input` component.
- **Files modified:** `packages/desktop-client/src/components/util/AmountInput.tsx`
- **Verification:** TypeScript compiles cleanly, `aria-required` and `aria-label` appear on the rendered input in the DOM
- **Committed in:** `189ceb726` (part of Task 2 commit)
