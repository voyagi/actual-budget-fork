## Accomplishments

- Added CORS origin restriction using ACTUAL_CORS_ORIGIN env var (defaults to localhost:3001 for dev)
- Added HSTS max-age=31536000 and Content-Security-Policy headers in non-development mode
- Added auth-specific rate limiter: 5 requests per 15 minutes on /account/login, /account/bootstrap, /openid/login

- Added USER node directive to Dockerfile so container process runs as non-root

## Decisions Made

- CORS origin uses String format (not Array) per plan decision - single allowed origin per deployment
- CSP includes style-src 'unsafe-inline' - required because React uses inline style objects
- Auth rate limiter mounted as `app.use([path1, path2, path3], authRateLimit)` before sub-app handlers, avoiding sub-app middleware complexity
- Default ACTUAL_CORS_ORIGIN is http://localhost:3001 - matches the dev React server port, safe for development without configuration

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test failures from 404 change and Boolean conversion**
- **Found during:** Task 3 (app-sync.ts changes), discovered at push time via pre-push test hook
- **Issue:** Changing `res.status(400)` to `res.status(404)` in verifyFileExists broke 8 tests expecting 400. Converting boolToInt to Boolean broke tests expecting integer 0/1 values. The `res.json(fileAccessError)` change broke 9 tests that checked `res.text` (res.json JSON-encodes strings with quotes, so `res.text` gets `"file-access-not-allowed"` not `file-access-not-allowed`).
- **Fix:** Reverted 404 to 400 (deferred to later), reverted Boolean back to boolToInt (deferred). Updated tests to check `res.body` instead of `res.text` for 403 file-access-not-allowed string responses (since res.json correctly sets Content-Type and res.body is the parsed JSON value).
- **Files modified:** packages/sync-server/src/app-sync.ts, packages/sync-server/src/app-sync.test.ts
