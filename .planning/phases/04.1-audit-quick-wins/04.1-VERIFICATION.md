### Human Verification Required

The following items pass automated checks but require manual browser/screen reader testing to fully confirm:

**1. Screen Reader Announcements**

**Test:** With NVDA or VoiceOver enabled, trigger a bank sync (or simulate changing accountsSyncing state). Navigate to the BudgetTotals view and change a budget amount.
**Expected:** Screen reader announces "Syncing... N accounts remaining" when sync starts, and announces updated budget totals when values change. Consent banners are announced when they appear.
**Why human:** aria-live regions cannot be verified programmatically for actual announcement behavior - only attribute presence can be confirmed.

**2. Focus-Visible Calendar Ring**

**Test:** Navigate to a date input field and press Tab to reach calendar day buttons. Verify a visible ring appears. Then click a day with the mouse.
**Expected:** Keyboard focus shows a 2px box-shadow ring; mouse click shows no focus ring.
**Why human:** :focus-visible behavior depends on browser input modality detection which cannot be verified by code inspection alone.

**3. Skip Navigation**

**Test:** Tab from the top of any page. Verify "Skip to main content" link appears. Press Enter. Verify focus moves past the sidebar.
**Expected:** Link appears visually on first Tab press; activating it places focus at the main content area.
**Why human:** Focus placement and skip-nav visual reveal require browser rendering and keyboard interaction.

**4. Urgency Icon Visual Distinctiveness**

**Test:** With active Enable Banking sessions at different urgency levels (soon/urgent/expired), verify each banner shows a distinct icon shape.
**Expected:** Soon = info circle, Urgent = exclamation outline, Expired = exclamation solid (filled).
**Why human:** SVG icon rendering and visual appearance can only be confirmed in a running browser.

**5. Auth Rate Limiting (429 Response)**

**Test:** Make 6 POST requests to /account/login within 15 minutes from the same IP.
**Expected:** First 5 succeed or fail normally; 6th returns HTTP 429 with `{ status: 'error', reason: 'too-many-requests' }`.
**Why human:** Rate limiting behavior requires actual HTTP requests against a running server.
