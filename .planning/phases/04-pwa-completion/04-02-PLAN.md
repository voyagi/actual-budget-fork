Start the app in a way that exercises the built PWA (not dev mode, since dev mode SW behavior differs from production).

Option A (Docker - preferred, matches production):
```
docker compose up --build -d
```
Then open Chrome to `https://localhost` (or the configured Caddy HTTPS URL).

Option B (Local production preview):
```
cd packages/desktop-client && npx vite preview --port 5173
```
Then open Chrome to `http://localhost:5173`.

Once the app is running in Chrome:

1. Open Chrome DevTools (F12) > Application tab
2. Check "Service Workers" section:
   - A service worker should be listed as "activated and is running"
   - Source should be `sw.js`
   - If status shows "waiting" that is OK (expected on first visit with registerType: 'prompt')
3. Check "Manifest" section:
   - All fields should be populated: name, short_name, start_url, display, theme_color, background_color
   - Icons should show 4 entries (192+512, any+maskable)
   - "Installability" section should show no errors
   - Note any warnings (some are informational, not blocking)
4. Check "Storage" > "Cache Storage":
   - Workbox precache entries should be visible
   - Verify .wasm and .sql files appear in the cached assets list
5. Run Lighthouse PWA audit:
   - Chrome DevTools > Lighthouse tab > Check only "Progressive Web App" category > Generate report
   - Document the score and any failed audits
   - Key checks: installable, works offline, has valid manifest, has service worker

Document all Chrome DevTools findings in detail. If there are installability warnings, document them with the exact warning text. If Lighthouse reports failures, document which specific audits failed.

For iOS deferral: No action needed. PWA-04 requires trusted HTTPS cert (Caddy local CA not trusted by iOS Safari). Document in the SUMMARY that iOS PWA install verification is deferred to Phase 5 when Cloudflare Tunnel provides a real domain cert.
