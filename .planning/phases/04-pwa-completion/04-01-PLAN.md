  <action>
The EnableBankingExternalMsgModal uses `width: 'clamp(400px, 30vw, 600px)'` (line 330). The clamp minimum of 400px exceeds the 375px mobile viewport width, causing horizontal overflow on narrow phones.

Fix the modal width in `EnableBankingExternalMsgModal.tsx` line 330:

Change:
```
containerProps={{ style: { width: 'clamp(400px, 30vw, 600px)' } }}
```

To:
```
containerProps={{ style: { width: 'clamp(300px, 85vw, 600px)' } }}
```

Rationale for new values:
- `300px` minimum: readable minimum that fits comfortably on 320px screens (smallest supported)
- `85vw` preferred: scales with viewport, leaves 7.5% margin on each side on mobile
- `600px` maximum: unchanged, prevents over-stretching on large screens

Also audit these other fork-specific components for 375px overflow (read each file, check for hardcoded widths exceeding 375px):

1. `packages/desktop-client/src/components/banksync/AccountRow.tsx` - Uses Cell/Row table components. These inherit table layout from upstream and should flex. Verify no hardcoded width > 375px.

2. `packages/desktop-client/src/hooks/useEnableBankingStatus.ts` - Hook only, no UI. Skip.

3. `packages/desktop-client/src/utils/consent-urgency.ts` - Utility only, no UI. Skip.

If AccountRow or any other fork component has hardcoded widths > 375px, apply similar clamp or max-width fixes. If they all use flex/percentage layouts, document as "verified responsive" in the commit message.

Do NOT modify upstream components. Only fix fork-specific files (files in app-enablebanking/, banksync/, or containing EnableBanking/consent-urgency logic).
