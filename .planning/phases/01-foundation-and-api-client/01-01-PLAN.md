  <name>Task 2: Create sync-server Dockerfile and docker-compose.yml, build and run</name>
  <files>
    packages/sync-server/Dockerfile
    docker-compose.yml
  </files>
  <action>
    **Step 1 - Read upstream build scripts:**
    - Read `packages/sync-server/package.json` to find the `build` and `start` scripts.
    - Read `bin/docker-start` if it exists to understand the upstream dev entrypoint.
    - Read the root `package.json` for workspace configuration.
    - Read the upstream `Dockerfile` (at repo root) and `docker-compose.yml` to understand the existing dev setup.

    **Step 2 - Create `packages/sync-server/Dockerfile`:**
    - Base image: `node:22-bookworm-slim`
    - Working directory: `/app`
    - Build context is the monorepo root (set in docker-compose.yml), so COPY brings the full repo.
    - Install Corepack and activate Yarn 4.10.3.
    - Run `yarn install` to install all workspace dependencies.
    - Run `yarn workspace @actual-app/sync-server build` to compile the sync-server (TypeScript compiles to `packages/sync-server/build/` via `tsc`).
    - Run `yarn workspace @actual-app/web build` to build the static frontend (Vite outputs to `packages/desktop-client/build/`). Note: the desktop-client package is named `@actual-app/web` in package.json, NOT `@actual-app/desktop-client`.
    - Expose port 5006.
    - CMD: `["node", "packages/sync-server/build/app.js"]` - this is the confirmed entrypoint (sync-server's `start` script runs `node build/app`).
    - Set `ACTUAL_DATA_DIR=/data`.
    - Do NOT set `ACTUAL_WEB_ROOT` explicitly. The sync-server's `load-config.js` resolves it automatically via `require.resolve('@actual-app/web/package.json')` + `/build`, which points to `packages/desktop-client/build/` within the container's `/app` working directory. This auto-resolution is more robust than hardcoding a path.

    **Step 3 - Replace `docker-compose.yml`:**
    - The upstream docker-compose.yml is for dev only. Replace it entirely with a fork-specific one.
    - Single `docker-compose.yml` (per locked decision) supporting both dev and prod via env vars.
    - Structure:
      ```yaml
      services:
        sync-server:
          build:
            context: .
            dockerfile: packages/sync-server/Dockerfile
          environment:
            - NODE_ENV=${NODE_ENV:-production}
            - ACTUAL_PORT=5006
            - ACTUAL_DATA_DIR=/data
            - ENABLE_BANKING_APP_ID=${ENABLE_BANKING_APP_ID:-}
            - ENABLE_BANKING_KEY_PATH=/run/secrets/eb_private.pem
            - ENABLE_BANKING_BASE_URL=${ENABLE_BANKING_BASE_URL:-https://api.enablebanking.com}
          ports:
            - "${SYNC_PORT:-5006}:5006"
          volumes:
            - actual_data:/data
            - ./secrets/eb_private.pem:/run/secrets/eb_private.pem:ro
          restart: unless-stopped

      volumes:
        actual_data:
      ```
    - Note: The `secrets/eb_private.pem` bind mount will fail if the file doesn't exist. Add a comment in the compose file about this. For initial Docker build testing (before the user has EB credentials), create a dummy PEM file: `openssl genrsa -out secrets/eb_private.pem 2048` (this test key won't auth with EB but allows Docker to start).

    **Step 4 - Handle the bind mount for initial build:**
    - Generate a temporary test RSA key so Docker can start without real EB credentials:
      `openssl genrsa -out secrets/eb_private.pem 2048`
    - This key is on the gitignored `secrets/` path so it won't be committed.
    - The user will replace it with the real sandbox key in Plan 02.

    **Step 5 - Build and run:**
    - Run `docker compose build` - must complete with no errors.
    - Run `docker compose up -d` - container must start.
    - Run `docker compose logs sync-server` - check for startup errors.
    - Verify the app is accessible: `curl -s -o /dev/null -w "%{http_code}" http://localhost:5006` should return 200.

    **Step 6 - Commit:**
    - Stage: `packages/sync-server/Dockerfile`, `docker-compose.yml`
    - Commit message: `feat(sync-server): [eb] add Dockerfile and docker-compose for fork`
    - Push to origin.

    **Troubleshooting notes:**
    - If `yarn install` fails in Docker, check that `.yarnrc.yml` and `yarn.lock` are being copied correctly.
    - If the desktop-client (`@actual-app/web`) build fails, check for missing peer dependencies. It uses Vite and outputs to `packages/desktop-client/build/`.
    - If the UI shows 404, the `@actual-app/web` package build may have failed or the webRoot auto-resolution is broken. Check that `packages/desktop-client/build/index.html` exists inside the container: `docker compose exec sync-server ls packages/desktop-client/build/`.
    - On Windows/MSYS, Docker Desktop must be running. If `docker compose` fails with "daemon not running", start Docker Desktop first.

  </action>
