    **Step 4 - Create `packages/sync-server/src/app-enablebanking/enablebanking-service.js`:**
    - Import `importPKCS8` and `SignJWT` from `jose`.
    - Import `readFileSync` from `fs`.
    - Import `axios` (default import).
    - Read config from env vars:
      - `ENABLE_BANKING_BASE_URL` defaulting to `https://api.enablebanking.com`
      - `ENABLE_BANKING_APP_ID` (required, no default)
      - `ENABLE_BANKING_KEY_PATH` defaulting to `/run/secrets/eb_private.pem`
    - Implement `loadPrivateKey()`: reads PEM from `ENABLE_BANKING_KEY_PATH`, calls `importPKCS8(pem, 'RS256')`, caches the result in a module-level variable. Lazy-loads on first call.
    - Implement `generateJWT()`: uses `loadPrivateKey()`, creates JWT with:
      - Header: `{ alg: 'RS256', typ: 'JWT', kid: ENABLE_BANKING_APP_ID }`
      - Payload: `iss: 'enablebanking.com'`, `aud: 'api.enablebanking.com'`, `iat: now`, `exp: now + 3600`
      - Signs with the cached private key.
    - Implement `ebRequest(method, path, data)`: calls `generateJWT()`, makes axios request to `${baseUrl}${path}` with `Authorization: Bearer ${jwt}`.
    - Implement `testAuth()`: calls `ebRequest('GET', '/application')` and returns `response.data`. This endpoint returns the application metadata if the JWT is valid.
    - Export all four functions as named exports.

    **Step 5 - Create `packages/sync-server/src/app-enablebanking/app-enablebanking.js`:**

    - Import `requestLoggerMiddleware` and `validateSessionMiddleware` from `../util/middlewares.js`.

This is an unauthenticated health-check route specifically for verifying JWT auth against Enable Banking during development. It is placed before the session middleware so it does not require a logged-in Actual user session:

    - Apply `express.json()`.

      - If present, call `testAuth()`.
      - On success: return `{ status: 'ok', data: { configured: true } }`.
      - On error: return `{ status: 'ok', data: { configured: false, reason: err.message } }`.

  <action>
    **Step 1 - Rebuild the Docker image with new code:**
    - Run `docker compose build` to rebuild with the EB adapter code and new dependencies.
    - Run `docker compose up -d` to start with the real sandbox credentials (from Plan 02's .env).

    **Step 2 - Test Enable Banking auth via the unauthenticated test route:**
    - Use the `GET /enablebanking/test-auth` route created in Task 1. This route is placed before `validateSessionMiddleware` and requires no Actual user session, making it ideal for automated testing.
    - Run: `curl http://localhost:5006/enablebanking/test-auth`
    - Expected response: `{ "status": "ok", "data": { "configured": true } }`
    - If `configured: false` with a reason, debug the JWT generation or key loading.
    - This proves the RSA key + JWT signing + Enable Banking API communication all work end-to-end.
    - The session-authenticated `POST /status` route will be used by the frontend in later phases.

    **Step 3 - Verify RSA key persistence (Phase 1 success criterion #3):**
    - Run `docker compose down`
    - Run `docker compose up -d`
    - Wait for the container to be healthy.
    - Test the test-auth endpoint again: `curl http://localhost:5006/enablebanking/test-auth`
    - Expected: same `configured: true` response, proving the key file survived the container lifecycle.

    **Step 4 - Verify container logs are clean:**
    - `docker compose logs sync-server` should show startup without errors related to Enable Banking.
    - The key loading happens lazily on first /status call, so no EB-specific logs on startup is expected.

    **Troubleshooting:**
    - 401 from Enable Banking API: JWT is malformed or key doesn't match. Check that the key in secrets/ is the one downloaded from enablebanking.com/cp. Verify APP_ID matches.
    - "ENOENT" for key path: The bind mount failed. Check docker-compose.yml volume mapping and that `secrets/eb_private.pem` exists on the host.
    - "unsupported algorithm" from jose: The key may be in PKCS#1 format (`BEGIN RSA PRIVATE KEY`) instead of PKCS#8 (`BEGIN PRIVATE KEY`). jose's `importPKCS8` requires PKCS#8. If the Enable Banking download gives PKCS#1, convert: `openssl pkcs8 -topk8 -inform PEM -outform PEM -nocrypt -in secrets/eb_private.pem -out secrets/eb_private_pkcs8.pem` and update the file.
    - The `GET /test-auth` route bypasses session middleware, so no workaround is needed for testing. If it still fails, try calling testAuth() directly inside the container: `docker compose exec sync-server node -e "import('./build/app-enablebanking/enablebanking-service.js').then(m => m.testAuth().then(console.log))"`.
